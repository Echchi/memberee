## 🗂 구조 변경

### 📁 pages

- ❌ 현재 로그인 필요/불필요 화면이 혼재되어 가독성 낮음
- ✅ `/app/(protected)`, `/app/(public)` 등으로 명시적 구분 필요

### 📁 components

- ❌ 컴포넌트가 페이지 디렉토리 안에 개별적으로 흩어져 있어 접근성 떨어짐
- ✅ 각 페이지 디렉토리 내부에 `components`, `hooks` 디렉토리 추가하여 분리
- ✅ 공통 컴포넌트만 `components/` 루트에 위치 (공통 컴포넌트 역시 관심사에 따라 재구성)

### 📁 components 세부 재구성

- `output/` : PDF, Excel 등 출력 관련
- `datetime/` : 날짜, 시간 관련
- `input/` : input, select, search 등 입력 요소
- `pagination/` : 페이지네이션, 무한 스크롤 등 관련 컴포넌트 분리

## ✅ 리팩토링 시 공통 원칙

1. **서버 컴포넌트 우선 사용**: 가능하면 서버 컴포넌트 우선 도입 (Next.js의 장점 활용)
2. **모듈화 & 품질 관리**: 관심사 분리, 공통화, 테스트 가능한 구조 지향
3. **디렉토리 구조 명확화**: 페이지/기능 기준으로 분리하고, 역할 기반 정리
4. **타입 안정성 확보**: `any`, `never` 사용 금지. 명확한 인터페이스 활용
5. **성능 최적화**: `useMemo`, 로딩 페이지, prefetch 등 적극 활용
6. **Git 브랜치 전략 & PR 문서화**: 브랜치 전략 명확히, PR에 변경점 & 의도 명시
